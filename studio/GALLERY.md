# Live gallery

The source is the publicly shared Drive folder `1Z80OtvvGuXiz9U2mYhVg8sPtFkGDIwjj`.

The site reads Google's public embedded-folder listing on the server. It does not store account credentials, require visitors to sign in, or use a build-time copy of the media list. The feed is revalidated at most every 60 seconds per server instance. The gallery checks again every 60 seconds while visible, when returning to the tab, and when Refresh is clicked. Short-lived image responses may be cached for five minutes.

Images and videos added to the folder's top level appear on the next successful refresh once Google exposes them in its public listing. Removed entries disappear. Subfolders and non-media files are skipped. The folder and its media must remain publicly viewable. Google's public embed markup is an upstream dependency: if Google changes it, `lib/gallery-source.mjs` may need an update. A Drive API integration would be the more durable choice for a larger collection.

Thumbnails are served through a restricted same-origin route that only accepts IDs currently present in this folder. Large video files are not downloaded or bundled; clicking a film opens Google's streaming preview. Google may still be processing an upload or may restrict playback. The viewer includes a direct link to the original file.

If the upstream listing fails, an explicit error appears. A server instance may retain the last valid listing for up to five minutes, marked stale. No unrelated demonstration media is substituted.

Source pages are in `site/`, client assets in `public/`, and server routes in `app/`. `dist/` is generated by the supported Sites/Vinext build. Preserve the existing project ID in `.openai/hosting.json`.
